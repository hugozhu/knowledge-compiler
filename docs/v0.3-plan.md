## 0. 环境事实

与 V0.2 相同（零第三方依赖、无 numpy、NPU ~16 tok/s、无本地 embedding 端点）。V0.3 **不需要新依赖、不需要 Schema 迁移**——图谱用既有 `relations`/`entity_mentions` 表，演化用 claims 生命周期列，产物视图落 Markdown 文件。LLM 调用只出现在 audit 判定与 digest 综合（小批量、可控）。

---

## 1. V0.3 范围

**做：**

1. **`kc remove <doc_id> [--purge-raw]`**：安全删除文档——FK 级联清 chunks/claims/mentions/relations、手工清 embeddings 孤儿、**恢复被该文档取代/判重的跨文档 claim**、回收孤儿实体、清 compile_log（保证 re-add 可重新编译）。raw 默认保留（immutable 原则），`--purge-raw` 显式覆盖。
2. **`kc graph`**：轻量知识图谱视图（Principle 9：只用 SQLite，不上 Graph DB）——全局概览（实体/关系统计、谓词直方图、连接度 Top）+ `kc graph <名称>` 实体邻域（出入边关系、共现实体、提及文档、相关论断）。
3. **`kc evolution [claim_id]`**：知识演化视图——superseded 链（旧观点 → 新观点 + 时间 + 理由）与 duplicate 记录，呼应提案 §17「记录认知如何变化」。
4. **`kc backlinks`**：自动反向链接——为每个实体生成 `entities/<type>/<id>-<slug>.md`（别名、提及文档、相关论断、关系），纯确定性生成、幂等、编译后自动刷新（`--no-backlinks` 逃生舱）。
5. **`kc audit [--apply] [--threshold] [--max-pairs]`**：矛盾巡检——active claims 两两向量候选（cosine ≥ 阈值）→ LLM 批量判定（contradiction / duplicate / consistent / unrelated）→ 报告；`--apply` 时矛盾形成 superseded 链、重复标 duplicate_of。与编译时判重互补（编译时判新 claim vs 全库；audit 是离线全库巡检）。
6. **`kc digest [--weekly] [--date] [--dry-run] [--compile]`**：日报/周报——收集周期内新增 docs/claims/entities → LLM 要点综合 → 写 `daily/YYYY-MM-DD.md` / `weekly/YYYY-Www.md`。`--compile` 可把 digest 喂回 inbox（知识闭环的雏形）。

**不做（V1.0）：** Memory 层、Context Builder、Web API、Graph DB、实时事件监听。

## 2. 模块设计

```
src/kc/
├── lifecycle.py   # remove_document：级联 + 演化恢复 + 孤儿回收
├── graph.py       # overview / resolve（含别名）/ neighborhood（出入边/共现/文档/论断）
├── backlinks.py   # 实体页生成（复用 graph.neighborhood），entities/<type>/ 全量重建
├── audit.py       # candidate_pairs（O(n²) 纯 Python cosine，90 条≈秒级）
│                  #   → judge_pairs（4 对/批）→ apply（矛盾=旧被新取代；重复=dup 标记）
├── digest.py      # collect_period → LLM 综合 → daily/weekly markdown
└── cli.py         # 新命令：remove / graph / evolution / backlinks / audit / digest
                     compile 挂 backlinks 钩子；watch 编译轮次后同样刷新
```

关键语义：

- **remove 的演化恢复**：`superseded_by`/`duplicate_of` 指向被删文档 claim 的，恢复 `status='active'`（那些知识本身仍有效）；恢复的 claim `dedup_checked=1`（无需重判）。
- **audit 与 dedup 分工**：dedup 在编译时处理「新 claim vs 库」；audit 处理「库内存量」，判定结果走同一套生命周期字段，`evolution`/检索自动生效（非 active 不入召回）。
- **backlinks 是视图不是源**：实体页由 DB 确定性生成、整树重建，**不**回灌编译（避免自引用噪声）；`entities/` 目录归生成器所有。
- **digest 防空转**：周期内无新增时明确提示不写文件；`--dry-run` 只打印收集统计。

## 3. CLI 一览（新增部分）

```bash
./kc remove <doc_id> [--purge-raw]      # 删除文档（raw 默认保留）
./kc graph [名称]                       # 概览 / 实体邻域
./kc evolution [claim_id]               # 演化链 / 指定 claim 的链
./kc backlinks                          # 手动刷新实体页（编译后自动）
./kc audit [--apply] [--threshold 0.3] [--max-pairs 50]
./kc digest [--weekly] [--date YYYY-MM-DD] [--dry-run] [--compile]
./kc compile [--no-backlinks]           # 新增逃生舱
```

## 4. 验收标准（DoD）

1. **remove**：级联干净（docs/chunks/claims/mentions/relations/embeddings/compile_log 全清）；raw 默认保留、`--purge-raw` 生效；**同文件 re-add 能重新编译**（compile_log 已清）；被删文档取代的跨文档 claim 恢复 active；孤儿实体回收
2. **graph**：概览输出统计 + 谓词 Top + 连接度 Top；`kc graph "VENTUNO Q"`（经别名解析）输出出入边、共现实体、提及文档、相关论断
3. **evolution**：无记录时友好提示；有记录时呈现完整链（旧→新、时间、理由）；`claim_id` 参数可查单链
4. **backlinks**：`entities/<type>/` 页面生成（含别名/文档/论断/关系），重复执行幂等，编译后自动刷新
5. **audit**：构造含矛盾论断的文档以 `--no-dedup` 编译（矛盾不落标）→ `audit` 检出 → `--apply` 形成演化链 → `evolution` 可见 → `remove` 后恢复；全库巡检报告近重复对
6. **digest**：生成 `daily/YYYY-MM-DD.md`（统计 + LLM 综合 + claim 清单带来源）；`--dry-run` 只统计；空周期明确提示
7. **回归**：V0.1/V0.2 关键路径（compile 增量 / search 双模式 / ask / entities / dedup）不回归
8. **文档同步**：本计划状态表、README、AGENTS 更新；issue 关闭

### 实现过程中的实测记录（相对本计划的差异）

1. **audit 首跑即命中提案的标志性例子**：`#47「AI Coding 最大问题是模型能力不足」vs #48「…是 Context / Harness」`——正是提案 §17 举的认知演化范例，被正确判定为矛盾并形成演化链（audit 全库 18 对候选：矛盾 5 / 重复 1 / 一致 10 / 无关 2）。
2. **4B 判定误判如实保留**：如 `#38 vs #59` 被判矛盾（实际是不同维度），符合计划「已知取舍」预期——机制可审计（`evolution` 出理由），误判可手工改 status 修正。
3. **演化链的级联副作用**：audit 可能形成 A→B→C 链（如 #47→#48→#59）；`remove` 只恢复指向被删文档的链（验证：删测试文档后 #39/#41 恢复、#47/#48 链保留）。
4. **实体页自动生成挂在编译尾部**：`compile --no-dedup` 测试时顺带验证了 backlinks 钩子（53 页自动刷新）；watch 轮次同样刷新。
5. **digest 分批综合**：82 条论断分 4 批综合（每批 ≤1800 字符），LLM 输出质量可接受且全部带来源标注；`--dry-run` 与空周期提示按设计工作。

## 6. 已知取舍

- **audit 的 O(n²) 候选**：纯 Python 两两 cosine 在千级 claims 内秒级可完成；到万级再优化（YAGNI）。默认 `neighbors=1` + `max_pairs=50` 控制 LLM 时长（约 6–12 分钟 @4 对/批）。
- **矛盾判定方向**：audit 一律「旧被新取代」（按 id/时间序），不做双向仲裁；误判可手工改 status（机制可审计 > 单次准确率，与 V0.2 结论一致）。
- **实体页不回灌**：backlinks 保持纯视图。若未来要把实体画像作为知识源，走显式 `--compile` 类开关，与 digest 一致。
- **digest 的综合质量**：受 4B 模型能力限制，定位是「清单 + 短综合」而非深度分析；深度综合属 V1.0 Cloud When Needed。
